Do dispositivo ao painel.

Este guia descreve a API que está disponível nesta versão do Smart Recycling. Comece verificando a conexão, configure a chave do dispositivo e só então envie medições reais.

Endereço base
https://mrvbot.com/smart_recycling
Use HTTPS em todas as requisições. O modo acadêmico aceita JSON simples em /api/eventos, /api/lixeiras e /api/dispositivos.

API acadêmica

Os três POSTs usam HTTPS e o cabeçalho Content-Type: application/json. As consultas, o painel e a documentação interativa usam o login atual.

Base https://mrvbot.com/smart_recycling. Use timestamps ISO 8601 em UTC, como os exemplos. Troque o horário pelo instante medido pelo equipamento.

Classificar um item

Envie para POST /api/eventos uma vez por item. Reuse o mesmo event_id e corpo se precisar reenviar após uma falha.

{
  "event_id": "daijwdji12jid1",
  "timestamp": "2026-11-22T19:24:14Z",
  "material": "organico",
  "metal": 0,
  "ir": 1,
  "color": [255, 255, 255],
  "rasp_material": "organico",
  "rasp_acuracia": 0.93,
  "acuracia_final": 0.95
}

material aceita organico, reciclavel ou indefinido. Os sensores digitais aceitam 0 ou 1. A cor segue RGB na faixa de 0 a 255. Os campos opcionais podem usar null quando faltarem leituras. As duas pontuações vão de 0 a 1.

Atualizar as lixeiras

Envie para POST /api/lixeiras a cada 60 segundos pelo ESP32 usando as medições do Arduino.

{
  "timestamp": "2026-11-22T19:24:14Z",
  "reciclaveis_cm": null,
  "organicos_cm": 30.1
}

Quanto menor a distância do sensor até o resíduo, mais cheia está a lixeira. O painel mostra os centímetros disponíveis. Para exibir percentual e alertas por ocupação, calibre as distâncias de vazio e cheio e envie o percentual pelo protocolo v1. A leitura acadêmica passa a aparecer como desatualizada após 150 segundos.

Informar o estado dos componentes

Envie para POST /api/dispositivos com os seis campos de estado.

{
  "timestamp": "2026-11-22T19:24:14Z",
  "sensor_indutivo": true,
  "sensor_cor": true,
  "sensor_ir": true,
  "raspberry": true,
  "servo_topo": true,
  "servo_calha": true
}

Use true para operante, false para indisponível ou null quando não há confirmação. O firmware confirma o sensor de cor pelos pulsos recebidos e o Raspberry pela resposta serial. O indutivo, o IR e os servos permanecem sem confirmação de funcionamento na ausência de diagnóstico elétrico dedicado. A classificação ainda pode carregar a leitura digital de IR e metal.

Enviar pelo terminal

Salve o corpo em um arquivo JSON e envie à rota correspondente. No Windows, use curl.exe.

curl -sS -H "Content-Type: application/json" --data-binary @evento.json https://mrvbot.com/smart_recycling/api/eventos
  • HTTP 201 confirma a gravação. HTTP 200 indica reenvio idêntico.
  • HTTP 409 indica que um ID já registrado foi reutilizado com outro conteúdo.
  • HTTP 422 indica divergência nos campos ou valores do JSON.
  • Os três POSTs acadêmicos são públicos e podem alterar o painel. Use o ambiente local para amostras de teste.
  • As consultas GET /api/eventos, GET /api/lixeiras e GET /api/dispositivos exigem sessão. O protocolo versionado /api/v1/events e os envelopes antigos continuam usando X-Device-Key.

Passo 1

Verifique se a API está disponível

Esta consulta é pública e não grava dados. No Windows, use curl.exe no lugar de curl.

curl https://mrvbot.com/smart_recycling/api/health

Resposta esperada: {"ok":true,"simulation_mode":false}. Isso indica que a API responde e que a simulação está desativada; não comprova que o hardware está conectado.

Passo 2

Escolha a credencial correta

Quem acessaAutenticaçãoUso
Pessoa ou script de consultaUsuário e senha → cookie de sessãoPainel, resumo, histórico, documentação e WebSocket.
ESP32 ou equipamentoCabeçalho X-Device-KeyEnvio de telemetria. Não usa a senha do painel.

Login para consultas por terminal

Crie um arquivo local login.json com seu usuário e senha. Não compartilhe esse arquivo. O exemplo abaixo usa marcadores: substitua-os pelas suas credenciais.

{
  "username": "SEU_USUARIO",
  "password": "SUA_SENHA"
}
curl -c cookies.txt -H "Content-Type: application/json" --data-binary @login.json https://mrvbot.com/smart_recycling/api/auth/login

A resposta é {"ok":true}. O arquivo cookies.txt guarda a sessão e deve ser tratado como uma credencial. A sessão dura até 8 horas; ao expirar, faça login novamente. Apague o arquivo local de senha após o uso. No Postman, envie o mesmo JSON em Body → raw → JSON; mantenha os cookies habilitados.

Como obter a chave do dispositivo

O responsável pela VPS encontra DEVICE_KEY no arquivo /opt/smart-recycling/.env, acessível por SSH. Peça essa chave ao administrador e configure-a no equipamento. Ela não é exibida neste tutorial nem enviada ao navegador. Nesta versão, a chave é compartilhada pelos dispositivos autorizados; device_id identifica a origem declarada, mas não é uma senha.

Passo 3

Envie uma medição real

Endpoint: POST /api/telemetry. Cabeçalhos: Content-Type: application/json e X-Device-Key: SUA_CHAVE.

Este exemplo é ilustrativo. Não envie os números abaixo para a produção. Substitua-os por leituras reais. Cada POST aceito grava uma linha e altera os totais do painel. Para testes sintéticos, use um ambiente local isolado.

Salve o JSON como telemetria.json. Use null para medições opcionais desconhecidas. Os campos metal e conveyor_running devem refletir os estados realmente informados pelo controlador.

{
  "device_id": "esp32-01",
  "simulated": false,
  "material": "reciclavel",
  "confidence": null,
  "metal": true,
  "infrared": 550,
  "color_r": 120,
  "color_g": 80,
  "color_b": 45,
  "distance_cm": 9.4,
  "organic_fill_pct": null,
  "recyclable_fill_pct": null,
  "organic_weight_g": null,
  "recyclable_weight_g": null,
  "conveyor_running": false,
  "servo_position_deg": null
}

Windows PowerShell

O terminal solicita a chave sem mostrá-la enquanto você digita. Use o JSON já preenchido com dados reais.

$chaveSegura = Read-Host "Chave do dispositivo" -AsSecureString
$chave = [System.Net.NetworkCredential]::new("", $chaveSegura).Password
$corpo = Get-Content -Raw -LiteralPath .\telemetria.json
Invoke-RestMethod -Method Post `
  -Uri "https://mrvbot.com/smart_recycling/api/telemetry" `
  -ContentType "application/json" `
  -Headers @{ "X-Device-Key" = $chave } `
  -Body $corpo
Remove-Variable chave, chaveSegura

Python, inclusive no Raspberry Pi

Use a biblioteca padrão do Python. O código solicita a chave e lê o arquivo com a medição, sem gerar valores.

import getpass
import json
import urllib.request
import urllib.error
from pathlib import Path

key = getpass.getpass("Chave do dispositivo: ")
payload = json.loads(Path("telemetria.json").read_text(encoding="utf-8-sig"))
request = urllib.request.Request(
    "https://mrvbot.com/smart_recycling/api/telemetry",
    data=json.dumps(payload).encode("utf-8"),
    headers={"Content-Type": "application/json", "X-Device-Key": key},
    method="POST",
)
try:
    with urllib.request.urlopen(request, timeout=15) as response:
        print(response.status, response.read().decode())
except urllib.error.HTTPError as error:
    print(error.code, error.read().decode())

Sucesso: HTTP 201, com {"id":123} (o número varia). O servidor registra o horário de recebimento e notifica o painel pelo WebSocket.

Passo 4

Entenda os campos e as unidades

CampoFormato / unidadeRegra atual
device_idTextoObrigatório; 1 a 80 caracteres.
materialTextoObrigatório: organico, reciclavel ou indefinido, sem acentos.
simulatedBooleanoUse false. true é rejeitado na produção.
confidenceNúmero de 0 a 1 ou null0.92 representa 92% de confiança, não acurácia validada.
metalBooleanoDetecção do indutivo; padrão false se omitido. Não aceita null.
infraredNúmero ou nullLeitura bruta; escala depende da calibração do firmware.
color_r, color_g, color_bInteiros de 0 a 255 ou nullValores processados. Não enviar frequências brutas do TCS230 nesses campos.
distance_cmCentímetros ou nullNúmero não negativo.
organic_fill_pct, recyclable_fill_pctPercentual ou null0 a 100; calcular conforme a instalação e calibração física.
organic_weight_g, recyclable_weight_gGramas ou nullNão negativos. Converta kg para g antes do envio.
conveyor_runningBooleanoEstado informado pelo controlador; padrão false. Não prova movimento físico sem realimentação.
servo_position_degGraus ou null0 a 180; distinguir posição comandada de medição física no firmware.
O endpoint legado /api/telemetry não possui event_id, deduplicação nem timestamp de origem. O novo endpoint /api/v1/events oferece esses recursos. Reenviar o mesmo evento cria outro registro. Os totais contam leituras, não objetos únicos validados. Não envie telemetria periódica como se cada amostra fosse um novo resíduo.
Passo 5

Consulte os dados e acompanhe ao vivo

Depois do login no terminal, reutilize cookies.txt. Estes exemplos só consultam os dados.

# Resumo: total, organic, recyclable, undefined, latest, simulation_mode
curl -b cookies.txt https://mrvbot.com/smart_recycling/api/overview

# Leituras mais recentes, em ordem decrescente de ID (limite de 1 a 200)
curl -b cookies.txt "https://mrvbot.com/smart_recycling/api/readings?limit=40"

# Encerrar e revogar a sessão
curl -X POST -b cookies.txt https://mrvbot.com/smart_recycling/api/auth/logout

Sem hardware, o resumo contém latest: null e o histórico pode ser []. Zero nos totais significa nenhuma leitura registrada; null em uma medição significa valor desconhecido. Após 60 segundos sem nova leitura, o painel considera a telemetria desatualizada.

WebSocket no navegador

Abra o console de desenvolvedor nesta página após fazer login e execute o trecho abaixo. O navegador envia o cookie da sessão automaticamente. A conexão só notifica novas leituras; consulte o histórico antes para carregar dados anteriores.

const stream = new WebSocket("wss://mrvbot.com/smart_recycling/ws");
stream.onmessage = event => console.log(JSON.parse(event.data));
stream.onclose = () => console.log("Conexão encerrada. Verifique a sessão.");
const keepAlive = setInterval(() => {
  if (stream.readyState === WebSocket.OPEN) stream.send("ping");
}, 15000);
// Ao terminar:
// clearInterval(keepAlive);
// stream.close();

Formato de notificação: {"type":"reading","data":{...}}. Ao perder a conexão, reconecte com espera progressiva e refaça a consulta do histórico. O cookie do painel é necessário; a chave do dispositivo não autentica o WebSocket.

Passo 6

Conecte o ESP32

Para configurar o ESP32, baixe o firmware e siga o guia de equipamentos. O ESP32 usa as rotas acadêmicas por padrão e também oferece o modo v1. A sequência abaixo descreve a compatibilidade com o endpoint legado.
  1. Configure a rede Wi-Fi e mantenha o controle da esteira e os intertravamentos no Arduino, independentes da rede.
  2. Receba pela UART as medições reais do Arduino. Defina com o firmware os pinos, baud rate, framing e unidades; esta versão ainda não fornece esse adaptador pronto.
  3. Converta os dados para o contrato da tabela. Use JSON válido, com números e booleanos, sem unidades dentro dos valores numéricos.
  4. Faça um POST HTTPS para https://mrvbot.com/smart_recycling/api/telemetry, com os dois cabeçalhos indicados no passo 3.
  5. Configure a validação do certificado TLS com uma CA confiável e o relógio do dispositivo correto. Não use modo TLS inseguro.
  6. Considere o envio confirmado somente após HTTP 201. Em 401, corrija a chave; em 422, corrija o JSON. Após timeout, não reenvie automaticamente como se houvesse deduplicação: o registro pode já ter sido salvo.
  7. Abra o painel e confira a origem, a classificação, os valores e o horário. A aceitação de um JSON não substitui a validação física dos sensores.

Armazene a chave na configuração privada do dispositivo. Não a inclua em páginas públicas, capturas de tela ou repositórios. O acesso remoto de iniciar ou movimentar motores continua bloqueado.
